# 真实交互：安装与首次使用

当前包适用于 Apple Silicon Mac，系统最低 macOS 26。它包含本机后端与音频组件，无需安装 Python、Node.js 或知了 App。Apple 中文识别模型由系统管理，不包含在安装包中。

## 安装

1. 打开 DMG，把“真实交互”拖到 Applications（应用程序）。ZIP 包也可解压后将 App 放入应用程序。
2. 从应用程序打开 App。正式发布包使用 Developer ID Application 签名，并完成 Apple 公证和票据装订；首次打开时 macOS 仍可能询问是否打开互联网下载的 App。请从本项目的发布页获取安装包，并按需核对 SHA-256。受单位设备策略管控的 Mac 可能需要管理员批准。开发者自行构建的临时签名包与正式发布包不同，不能用来判断公开分发是否通过系统检查。
3. 首次打开自动创建当前用户的本机工作区，不会带入发布者的访问码、模型 Key 或会议资料，也不会自动收音。

Apple 官方说明：`https://support.apple.com/102445`。不需要关闭整台 Mac 的安全检查，也不提供移除隔离属性的脚本。

## 首次配置

首次打开，在空会议列表点击“首次设置”。之后也可从“设置 → 首次使用”选择要启用的功能。

1. 打开“设置 → 语音转写”。默认使用 Apple 中文识别，未就绪时点击“安装模型”。也可配置阿里云百炼用于实时会议和音频文件，或配置 DeepSeek 官方 ASR 用于音频文件。各用途用内置样本测试通过后，可以分别设为默认。两家的语音服务密钥与文字模型配置分开保存。
2. 在“设置 → 模型与搜索”的文字模型区域中选择协议/服务，填写 Base URL、模型名称和 API Key。使用实际服务支持的模型名和推理参数，点击测试，再保存设置。单独一个 Base URL 和 Key 不能决定模型名称，也不能保证所有厂商的非兼容接口可用。
3. 在网页搜索中选择 DeepSeek 或 Tavily，填写该搜索服务的地址和 Key，测试并保存。Tavily 使用自己的 Key；不要勾选复用文本模型 Key，除非服务确实共用凭据。配置搜索并不替代文本模型。
4. 没有云服务凭据时仍可录音与本地转写，但自动查证及 AI 纪要需要可用的文本模型，网页查证还需要搜索服务。联网配置测试可能产生实际服务请求和费用；App 免费不代表第三方 API 免费。

## 在飞书接收查证文档（可选）

进入“设置 → 飞书同步”，连接飞书账号，粘贴有写权限的飞书云空间文件夹链接。需要群提醒时，搜索并选择目标群，然后启用并保存同步设置。旁边的问号说明如何授权、建群和设置成员的阅读权限。点击“发送测试”后，确认在手机飞书能打开合成测试文档。

飞书连接使用本机另行安装和初始化的官方 `lark-cli`（本版验证版本为 1.0.100）。云文档权限由飞书管理。每次领取待发结果时会检查绑定身份。首次连接之前产生的文件不会自动补发。

## 完成第一场会议

建议先导入一段几十秒的普通测试音频，验证“导入 → 转录 → 问题查证 → 文档”。创建或导入时按该场会议确认是否允许转写发送给模型；需要网页查证时启用搜索。若没有识别出待查问题，可手动添加一个公开问题来验证服务配置。

实时开会时，选择“麦克风”“电脑声音”或两者，再开始收听。使用云端转写前，主持人确认本场发送的音源和接收服务。撤回授权后，应用停止继续上传，实时录音仍保存在本机。麦克风及系统音频捕获由 macOS 单独授权；第一次出现系统提示时按实际需要允许。双音源建议戴耳机，避免外放回声。导入文件无需开启麦克风。收到电平不等于识别已经成功，应看到实际转写后再开始正式会议。

结束会议后查看“会议文件”：应有录音、全量转录与会议纪要。若未收到某一路声音、模型服务未配置或请求失败，页面会显示相应状态；本地纪要草稿不等于 AI 总结已完成。会后仍可恢复或重试查证。

资料默认保存在 `~/Documents/ZSJH/Meetings/`。在“设置 → 保存与回看 → 会议文件保存位置”可以查看完整位置、打开文件夹或选择其他文件夹。选择成功后自动保存，新会议使用新位置；已有会议继续在原位置读写，不会自动搬迁。外接硬盘上的会议需要连接原硬盘后才能访问。

服务配置与本机数据库保存在 `~/Library/Application Support/ZSJH/Workbench/`，不随会议文件位置改变。会议资料长期保留，仅在用户主动删除会议时清除。实时录音归档为 M4A；设置可选择额外保留原始 CAF，导入文件保留原格式。

“设置 → 外观”可选跟随系统、浅色或深色，退出重开仍保留选择。

顶栏右侧可随时切换“静阅”和“全景”。静阅以舒展双栏呈现内容，便于专注阅读；全景在宽窗口同时展示转写、查证问题和回答，便于对照处理。窗口变窄时按当前标签显示，两种名称均完整保留。切换保留当前会议、问题和未提交内容，退出重开仍保留布局选择。“设置 → 通用 → 外观”也有相同入口。

## 当前验证边界

本地构建、Apple 公证和自动化测试不能替代第二台干净 Mac 的安装、Apple 模型下载、权限授权及所选服务的真实联网验收。每个正式发布包的签名、公证和 Gatekeeper 结果以该版本的发布记录为准；Apple 公证不代表 Apple 验证了转写准确率或第三方服务效果。Windows、Intel Mac、腾讯会议内 AI 双向发声不在本版支持范围内。

## 制作分发包

开发者先构建、验证 App，再执行：

```sh
/bin/zsh native/scripts/package-distribution.sh
```

默认在 `native/build/distribution/` 生成带版本号的 DMG、ZIP 和 SHA-256 文件。脚本不覆盖同名发布物，不读取用户工作区；包内包含第三方许可证。构建时应一并保留依赖许可与上游来源记录。

以上命令只制作开发分发包。正式签名、公证及验证使用 [正式发布流程](RELEASING.md)；仅在 App 和 DMG 都通过公证、装订与 Gatekeeper 验证后上传 GitHub Release。
