# 语音转写与云端 ASR 实施方案

> **For agentic workers:** REQUIRED SUB-SKILL: 使用 superpowers:executing-plans，按任务逐项实施、验证。默认单代理，按下列复选框记录实施和验收。

**Goal:** 将设置中的“本机转写”改为“语音转写”，保留 Apple 中文识别，增加可填写、可真实测试、可明确启用的云端 ASR。

**Architecture:** 沿用现有原生采音、本机录音和转写事件链路，在原生 AudioCore 中适配云端识别。Python 负责配置、测试凭据和会议使用权限，Swift 原生进程直接连接 ASR；实时会议和文件导入分别测试、分别选择转写方式。识别失败与采音失败分开，网络故障不再通过识别错误停止本机录音。

**Tech Stack:** 现有 Flask / Pydantic、HTML / JavaScript、Swift 6.0 工具链与 Swift 5 语言模式、macOS 26.0、AVFoundation、Apple Speech、Foundation URLSession / URLSessionWebSocketTask。首期不增加厂商 SDK 或音频中转服务器。

**Spec:** 本文件第 1 节记录用户 2026-11-21 的需求，第 2 节记录现场代码依据；其余章节是据此形成的设计建议。来源查阅截至 2026-11-21。

## 全局约束

- 保留 Apple 的中文识别、模型检查和显式安装流程；升级后的旧配置仍默认使用 Apple。
- 首期接入阿里云百炼 Fun-ASR（实时、文件）和 DeepSeek 官方 ASR（文件）。升级后的实时与文件默认值均为 Apple。
- 云端语音、文字模型和搜索独立配置；配置 ASR 不要求启用文字模型或搜索。
- 不自动把已有会议或原本选择 Apple 的音频上传云端。
- 实时、文件分别测试和启用；一项成功不能使另一项显示可用。
- 修改服务地址、密钥或相关模型后，相关测试结果失效；草稿和测试不影响当前正在使用的配置。
- 每次收听或导入固定服务配置。上传权限独立于配置快照，撤回对当前任务也生效。
- 先保存本机录音，再异步识别；云端网络等待不能阻塞录音写盘。
- 保留当前双音源独立处理，不把系统声和麦克风混成一路，也不把音源当作说话人身份。
- 延用现有会议、片段、修订和资料引用机制，不重做问题识别、资料生成或归档。
- 保留无关工作区改动。当前已有大量未提交变更，实施时不得整体还原、清理或一并提交。

## 3. 现成实现与接入选择

### 3.1 首期服务及适用场景

| 来源 | 可以借鉴的做法 | 本项目取舍 |
| --- | --- | --- |
| 百炼 Fun-ASR 实时官方 API [S1][S2] | WebSocket 任务生命周期、增量/最终结果、sentence_id | 首期实时适配；每个音源独立会话 |
| 百炼 Fun-ASR Flash 官方 API [S3] | 本地短音频通过 HTTP Base64 识别 | 文件分段上传，不要求先上传公网对象存储 |
| DeepSeek 官方语音识别 [S6] | 完整音频文件作为一次 HTTP 请求上传，返回整段文本 | 首期支持文件导入和会后录音转写。会中实时字幕由 Apple 或百炼提供 |
| OpenAI Realtime 转写官方指南 [S4] | 独立的实时转写会话与事件协议 | 证明不同厂商需要不同适配；首期不接入 |
| VoiceInk 开源仓库 [S5] | 保留本机、云端转写选择的产品方向 | 只参考入口组织，不直接搬代码；未完成当前提交及许可证适配审查 |

这次复用的是现有本机链路和厂商公开协议。没有找到经过本轮验证、能直接替换本项目双音源实时会议链路的现成组件，因此只增加薄的服务适配，不建设通用插件平台。

百炼推荐模型字段预填为实时 `fun-asr-realtime`、文件 `fun-asr-flash-2026-06-15`。模型名最终以所选区域、工作空间实际测试通过的值为准。服务端别名不能视为底层模型版本永远不变。

### 3.2 地址配置不能假装跨厂商通用

- 根据服务显示配置字段和可测试用途。百炼支持实时与文件，DeepSeek 仅支持文件。
- 百炼的服务地址填写百炼控制台提供的 BaseURL；可包含区域及工作空间信息。适配器生成实时 WebSocket 地址和文件 HTTP 地址，并只读展示解析结果。
- 不沿用文字模型的 `/chat/completions` 规范化函数；ASR 使用自己的地址校验和协议路径。
- 百炼的地址或密钥变化使其两项测试失效，修改某一种模型只影响该用途。DeepSeek 固定使用 `POST https://api.deepseek.com/v1/tools/asr`，使用独立的 Bearer API Key，界面只显示文件测试和只读地址。协议按音频自动识别语种，表单及请求均省去模型名和语言参数。[S6]
- 若将来增加火山、腾讯或 OpenAI，新增对应协议适配及测试，不能只换下拉选项和模型名。

## 4. 设置页面及使用流程

### 4.1 页面布局

```text
设置 → 语音转写

默认转写方式
  实时会议：  Apple 中文识别 / 阿里云百炼
  音频文件：  Apple 中文识别 / 阿里云百炼 / DeepSeek 官方 ASR

Apple 中文识别
  实时识别状态、文件识别状态
  [检查状态] [安装中文模型]

云端语音转写
  配置服务    阿里云百炼（Fun-ASR） / DeepSeek 官方 ASR
  选百炼时
  服务地址    控制台 BaseURL
  API Key     密码输入；已保存时显示“已配置”
  实时模型    fun-asr-realtime
  文件模型    fun-asr-flash-2026-06-15
  [测试实时转写] [测试文件转写]

  选 DeepSeek 时
  官方地址    https://api.deepseek.com/v1/tools/asr（只读）
  API Key     密码输入
  [测试文件转写]

  当前服务支持的用途分别显示测试状态。百炼示例：
  实时：未测试 / 测试中 / 测试通过 / 测试失败
  文件：未测试 / 测试中 / 测试通过 / 测试失败
  结果：识别文本、耗时、模型、测试时间或明确错误

  [✓] 云端识别异常时，Apple 已就绪则切回本机
  [保存并使用]
```

两个默认方式可以不同。例如百炼实时和 DeepSeek 文件各自测试通过后，可同时选为默认方式；界面要明确显示这一选择，不做隐式回退。

### 4.2 测试后启用

1. 编辑的是草稿。正在工作的服务和正在录音的会议继续使用原配置。
2. 点击测试后，发送随 App 提供的合成中文短音频；界面说明“将发送测试音频，可能产生少量服务费用”。测试不使用真实会议录音。
   测试创建独立识别会话，不调用正在录音的 AudioCore.start/stop、不占用麦克风，也不共用当前会议的识别会话。
3. 实时测试汇总各句最终版本，并等待任务正常结束。文件测试读取成功响应中的全文。两项分别用同一固定样本判定：忽略标点和空白后，必须先找到“语音转写”，再找到“完整识别”。临时结果不参与判定。
4. 展示实际最终文本和耗时。仅返回末句、空文本、关键词缺失或倒序均失败，标明原因（无文本时显示“未返回文本”），禁用该候选的相应用途。短测衡量接口能否识别固定样本，业务术语准确率和长会稳定性另行评估。
5. 只有该服务已通过测试的能力，才允许选择云端并“保存并使用”。未通过的另一项可以明确选择 Apple。
6. 保存时由后端核验候选配置指纹、原生测试记录和设置 revision；不能相信前端传来的 `tested=true`。
7. 修改相关字段或点击清除密钥后，旧测试不能用于新配置。切换地址不携带旧地址的密钥。
8. 测试取消或失败不覆盖当前可用配置。首期不增加持久化未测试草稿功能。

Apple 就绪检查与云端短音频测试分别显示。设置页可同时查看两者，实际任务只检查所选能力。

## 5. 配置、接口与原生数据流

### 5.1 配置职责

现有 `Services` 增加 `speech`，默认值兼容旧文件：

```json
{
  "speech": {
    "live_provider": "apple_local",
    "file_provider": "apple_local",
    "fallback_to_apple": true,
    "providers": {
      "dashscope": {
        "base_url": "",
        "live_model": "fun-asr-realtime",
        "file_model": "fun-asr-flash-2026-06-15",
        "api_key_configured": false
      },
      "deepseek": {"api_key_configured": false}
    },
    "verification": {
      "dashscope": {"live": {"status": "not_tested"}, "file": {"status": "not_tested"}},
      "deepseek": {"file": {"status": "not_tested"}}
    }
  }
}
```

上面是公开读取形态；私密配置保存 `api_key`，不保存公开计算字段。沿用现有私有配置文件、0600 和原子替换，不在本次顺带迁移所有凭据存储。

拟新增 `SpeechSettings`、`SpeechCloudConfig` 和 `SpeechSettingsUpdate`；使用 Pydantic 严格、冻结配置。仅更新指定服务，另一家的密钥、配置及通过记录照常保留。密钥独立于文字模型配置。后端测试记录绑定提供方、候选指纹、能力、原生客户端版本、测试结果及时间，不把密钥写入记录或错误。

旧版模型/搜索保存请求没有 `speech` 字段时，必须保留已有 ASR 配置；不能用默认 Apple 值覆盖已经启用的云端配置。

### 5.2 接口契约草案

| 接口 | 调用者与返回 | 关键约束 |
| --- | --- | --- |
| `GET /live/v2/settings` | 现有设置页面；增加 speech 脱敏字段 | 不回传已保存 Key |
| `POST /live/v2/settings/speech/tests` | 主持人提交 `provider`、候选和 `kind=live/file`，返回 test_id | 草稿仅短期内存保留；不启用服务 |
| `GET /live/v2/settings/speech/tests/<test_id>` | 页面查询进度和脱敏结果 | 只返回本次测试结果，不返回私密候选 |
| `POST /live/v2/settings/speech/tests/<test_id>/session` | 已认证的本机原生进程领取候选 | 绑定桌面实例、测试 ID 和用途；普通页面不能领取私密配置 |
| `POST /live/v2/settings/speech/tests/<test_id>/result` | 原生回报实际测试结果 | 校验实例与任务，不能由页面伪造通过 |
| `PUT /live/v2/settings/speech` | 主持人提交候选、默认选择、revision、对应 test_id | 核对指纹和通过记录后原子保存 |
| `POST /live/v2/meetings/<meeting_id>/speech-session` | 本机原生进程领取 live/file 固定快照 | 按 §7 核对主持人授权、会议、目的地、用途、音源及当前 `capture_epoch` 或 `import_id`；仅向绑定原生实例发放 |

后端在创建测试、保存选择和领取会议会话时均校验服务及用途。`deepseek/live` 在领取密钥或对外发请求前即被拒绝。原生也只为 `deepseek/file` 创建文件客户端。切换文件服务后，短测记录和会议上传授权均须匹配新目的地。

设置测试只允许使用包内样本。原生回报最终文本、协议结束状态及样本版本，后端按 §4.2 复核，再写入对应能力的测试记录。

测试任务最多同时一个；30 秒无结果标为超时，未完成候选 5 分钟清理。上述时间是设计参数，不是厂商 SLA。测试能力的指纹只包含相关 ASR 配置，不因修改文字模型而失效。

原生私密接口复用现有 loopback 认证基础，另校验原生实例绑定：在 `live/workbench_cli.py` 现有 ready 私密握手中增加每次启动生成的 speech 实例令牌，原生领取会话和回报结果时附带该令牌。令牌只留在后端和 DesktopHost 内存，不进入页面；不能仅凭普通 owner/agent 请求领取密钥。已测试的活动配置及脱敏结果可持久化，未启用草稿不持久化。短测成功不保证今后鉴权、额度或网络一直正常，实际任务仍处理这些错误。

### 5.3 音频流与转写事件

```text
原生采音 ─→ 本机录音写盘
        └→ 有界识别输入
             ├→ Apple：现有 LocalRecognition + TranscriptReducer
             └→ 百炼：PCM 转换 → WebSocket → 句子结果适配
                                    ↓
                     现有 transcript.* / segment / revision
                                    ↓
                     原有问题识别、查证、归档、资料引用
```

不把 PCM 或 Base64 音频加入 helper 的 stdout JSONL，不经前端或 Flask 中转会议音频。文件由原生解码、分段后直接请求 ASR。

共同接口输出已有 `TranscriptChange`，不新造另一套会议片段表示：

```swift
protocol SpeechSession: AnyObject, Sendable {
    var format: AVAudioFormat { get }
    var changes: AsyncThrowingStream<TranscriptChange, Error> { get }
    func append(_ buffer: AVAudioPCMBuffer) throws
    func finish() async throws
    func cancel() async
}
```

在 `SpeechSession.swift` 放最小接口、工厂和 Apple 适配。Apple 适配组合现有 `LocalRecognition` 与 `TranscriptReducer`；Apple 特有的主动 finalize 策略只留在本机分支。百炼按 `sentence_id` 稳定映射片段，不能靠 2ms 起始时间容差猜同一句。

`SpeechSessionConfig` 保存一次任务的提供方、地址、模型、配置 revision 和私密凭据；不进入公开 native state。helper 通过现有 stdin 私密命令接收，不把 Key 放命令行、URL 查询、stdout、会议导出或诊断日志。客户端不向重定向后的其他主机转发鉴权头。

增量和最终结果必须保留原始音频时间轴。若实时中间结果没有有效结束时间，使用已发送到该识别会话的音频末端作临时显示边界，最终结果再修订；没有有效最终时间的结果不能伪装成已确认最终片段。

### 5.4 文件识别的具体处理

- 沿用 `AudioFileInfo` 的格式、2GB / 6 小时限制及真实解码检查；云端按段处理，不把整个文件读进内存。
- 采用已有解码/采样率转换能力，输出 16kHz、16bit、单声道短片。设计目标段长 30 秒：20 秒后寻找至少 0.8 秒停顿，最迟 60 秒截段；无重叠、无丢样本。
- 百炼文件适配器使用 Flash 非流式 HTTP 返回的完整 `output.text`，不能把最后一个 `output.sentence` 当作整个分段的识别结果。
- DeepSeek 复用上述分段器，每段封装为带 WAV 头的 16 位 PCM、16 kHz 单声道文件，用 `multipart/form-data` 的 `file` 字段发送。双声道导入先在本机将左右声道下混，防止只保留左声道。发送前检查实际 WAV 大小不超过 8 MiB、时长不超过 120 秒，上传超时受官方 10 分钟上限约束。以上限制针对每次请求，长文件仍按本项目原有上限导入。[S6]
- DeepSeek 从响应顶层 `text` 取全文，`request_id` 可用于定位错误，`duration_ms` 表示该段音频时长。片段起止时间取本机解码位置。400/413 提示格式或大小问题，408/429/503/504 显示超时、限流或繁忙，沿用有限重试与取消策略。服务按音频时长计费，重发时沿用重新导入费用提示。[S6]
- 首期每个短片提交一个最终片段，以真实短片起止时间作为片段区间。它是段级定位，不能宣称每句话都有精确时间戳；后续需要句级定位时再增加对应服务结果解析。
- 片段 ID 绑定 import_id 和 chunk_index；转写及进度收到后端 ACK 后才标记该片完成。
- 一次最多一个请求，限流时有限重试。任务最终失败时保留旧会议的原音、已完成文本和首个失败分段的时间位置。按钮写“重新导入为新会议”，点击前显示将从头转写、云端可能重复计费。确认后创建新会议 ID 和新导入 ID，按新会议的转写方式和授权处理，旧会议可继续查看。
- 用户取消后取消未完成请求，拒绝旧 generation 的迟到响应；不能把部分完成显示成“导入完成”。

## 6. 真实会议中的故障处理

### 6.1 录音、识别分别显示与存储

新增 `asr.status`、`asr.gap`、`asr.error`；同步修改 Swift/Python 事件契约，增加脱敏的提供方和识别会话标识。保留当前 `audio.*` 的采音含义。

- `capture` 表示采集、设备和录音状态。
- `transcription` 按音源记录提供方、连接/识别/降级/暂停状态及缺口。
- 收到 ASR 事件只更新 transcription，不能覆盖 capture，也不能触发 `stopCapture`。
- 启动时先建立录音和采音链路，再异步连接识别。初次连接失败同样只影响识别，不得经 start 的统一异常处理回滚并停止录音。
- 权限丢失、设备或磁盘写入失败仍属于真实采音故障，保留停止及明确错误提示。
- 逐段隔离采音写盘、识别输入、helper 输出、DesktopHost 待提交队列及后端确认。采音回调不等待网络、stdout 或后端。相同音源的电平只留最新值，同一未定稿片段只留最新修订。替换这些事件不算缺口。
- 最终文本、缺口和录音状态走有界内存队列加本机待确认记录。helper 在后台保留关键事件至后端持久化确认，DesktopHost 按稳定事件 ID 转发确认，断连后幂等重送。按轮次、音源及原音时间登记未交付区间。待确认记录达到磁盘配额时暂停识别，把连续未确认区间合并为缺口，保留录音与收尾记录所需空间。无法保存缺口时报告保存失败。
- helper 输出积压、桌面队列满、提交失败只影响转写交付。区分输出暂时不可用与宿主真正退出，后者按 §6.3 收尾。录音设备断开、录音写盘失败仍报告真实采音故障。

界面可显示“录音中 · 云端连接中”“录音中 · 已切回 Apple”“录音中 · 转写暂停，音频已保存”，不能用一个笼统的“出错”覆盖全部状态。

### 6.2 有限重连和 Apple 降级

以下都是首期拟定上限，实施时用故障注入验证：

| 情况 | 处理 |
| --- | --- |
| 短暂断线、超时、5xx | 最多重连一次，恢复等待预算 5 秒；预算内无法恢复则进入降级或录音继续状态 |
| 401 / 403、模型不存在、额度明确耗尽 | 不循环重试；显示地址/密钥/模型/额度的具体错误类别 |
| 429 | 仅在恢复预算内尊重 Retry-After；不无限等待和重复请求 |
| Apple 已安装，允许降级 | 单次收听内最多从云端切回 Apple 一次；本次不自动再切回云端 |
| Apple 未就绪或降级关闭 | 继续本机录音，提示“转写暂停”，标记未确认区间；不现场自动下载模型 |
| 停止/结束中发生错误 | 继续完成录音关闭、最终结果收尾和 ACK；不能为了重连无限拖住结束 |

发送队列最多缓存 5 秒待发 PCM；另保留最近 10 秒有界音频缓存用于切换边界。超过上限的未确认音频记录缺口，不无限积压。限制按音频帧数计算，不能靠不定大小的 buffer 条数估算。

每个音源记录识别 generation、已确认区间与切换边界。Apple 回放只取缓存内未确认的尾部；太旧区间标缺口。旧云端会话结果在切换后被隔离，不能覆盖新结果或把同一音频区间提交两次。切换时撤回未确认的临时片段。

缓存重放从内存取得，不假设正在写入的 CAF 可以安全并行读取。停止后保存完整原音，以便重新导入转写。

### 6.3 停止、结束和恢复范围

- 开始采音前，后端在活动会议中登记 `capture_epoch`，对 Apple 和云端使用相同规则。停止时先停止接收新音频，再收齐最终文本或登记缺口，然后确认各音源录音已关闭且可读。
- 百炼要发送结束任务并等待最终结果和 task-finished；不能关闭 WebSocket 后就宣布转写完整。
- 实施时统一停止预算：识别最终等待最多 4 秒，原生总收尾预算 10 秒，页面等待预算 14 秒；按总 deadline 而非各音源串行累计。现有原生 7 秒 watchdog 需同步调整。
- 后端按会议和 `capture_epoch` 持久化收尾结果。仅在所有音源的最终文本和录音状态都已确认时记为“已完整保存”。有未确认区间时，录音保存成功且后端确认了对应缺口，才记为“已保存录音且缺口已登记”，并向用户展示缺口。一路明确未收到音频时，保留另一路已校验的录音，并将本轮标为有缺失。若某路保存失败，记录实际失败原因并保留原文件。关键记录无法保存或末次确认无法核实时显示“保存失败”或“仍在收尾”，允许幂等查询与重试。
- 后端在同一事务或同一会议锁内检查全部轮次并结束会议，与开始新轮次互斥。只有上面两个已保存结果可以放行，没有采音轮次的会议沿用现有结束流程。当前页、其他窗口及原生退出共用这一判断。退出超时保留本机待确认记录和活动会议，下次启动可重试，不能把进程退出或页面解除绑定当作保存完成。
- 已结束会议保留原音、已确认文本和缺口。会后补转或失败导入均走 §5.4 的“重新导入为新会议”，不向 ended 会议插入新片段。

## 7. 音频上传选择与文案

会议单独保存主持人批准的上传范围，包括实际服务目的地（提供方、规范化端点、区域及工作空间）、用途（实时或文件）、音源集合和授权版本。旧会议无授权时仅可在本机处理。设置页短测和保存默认方式均不授权上传会议音频。

- 首次选择云端时，在创建或导入操作中展示接收方、用途和实际音源，由主持人确认。更换目的地、从实时改为文件或新增麦克风等超出范围的操作均须重新确认。暂停后在原范围内恢复无需重复弹窗，但领取会话仍须绑定本次轮次或文件任务。
- 后端从当前任务及服务配置计算实际范围，核对会议 ID、授权版本、音源及当前 `capture_epoch` 或 `import_id`。错误轮次、越权音源、过期授权或非主持人尝试扩大权限均拒绝；旧查证表单省略语音字段时只更新原字段，保留上传授权。
- 主持人可在会中撤回。后端立即拒发新会话并通知 DesktopHost 和 helper 撤销当前授权版本。原生发送端停止提交新的 PCM 或文件分段，丢弃排队数据，取消在途请求、重试及重连，并回报已停止。控制通道断开时以短时授权租约到期停传；界面在收到停传确认或租约失效前显示“正在停止上传”。已发出的音频无法收回，本机录音继续，未确认区间登记缺口。
- 选择 Apple 时继续说明“音频在本机处理”。文字模型是否收到转写文本，仍由原有权限控制。
- 对引导、空状态、来源说明、新建/导入、开始按钮、设置提示中的“本机转写”“音频只留本机”逐处核对：页面名称统一“语音转写”，实际处理说明按选择动态展示。
- 历史会议记录实际使用提供方；修改默认服务不能改写历史会议的来源说明。

## 9. 验证命令与明确验收标准

可用下列命令复跑离线验证。

```bash
.venv-live/bin/python -m unittest discover -s tests -p 'test_speech_settings.py'
.venv-live/bin/python -m unittest discover -s tests -p 'test_speech_sessions.py'
.venv-live/bin/python -m unittest discover -s tests -p 'test_provider_settings.py'
.venv-live/bin/python -m unittest discover -s tests -p 'test_workbench_audio_import.py'
.venv-live/bin/python -m unittest discover -s tests -p 'test_audio_archive_integration.py'
.venv-live/bin/python -m unittest discover -s tests -p 'test_workbench_frontend_contract.py'
swift test --package-path native
.venv-live/bin/python tools/verify_meeting_workbench.py --native --output outputs/cloud-asr-verification
```

现有综合脚本的 --native 是不调用 Apple 框架的 smoke，不能替代上面的 Swift 测试或真实桌面会议验证。新增 SpeechProbe 的真实调用不纳入默认离线测试，避免 CI 自动产生费用。

| 验收项 | 通过条件 |
| --- | --- |
| DeepSeek 文件转写 | 最终 App 的独立文件短测通过，右声道独有语音可识别，超过 120 秒的录音经分段得到完整有序文本。实时列表无 DeepSeek，后端拒绝该组合。更新 DeepSeek 密钥不改变百炼实时的通过状态 |
| 向后兼容 | 旧配置不触发任何云端请求；Apple 的实时、导入、安装行为继续可用 |
| 配置独立 | 模型/搜索关闭时 ASR 可单独用；两者保存不会丢 ASR 设置 |
| 测试可信 | 实时与文件各自取得最终响应，首尾关键词按序出现；仅末句、空文本、倒序、前端伪造及指纹失效均不能启用相应用途 |
| 录音安全 | 云端错误、helper 输出阻塞、桌面队列满和后端提交失败下，两路录音均持续增长且可解码；未保存转写有音源和时间区间，实际设备故障另行报告 |
| 结果一致 | 同一事件重试幂等；旧会话不能污染当前会话；final 更正仍触发原有引用失效处理 |
| 文件完整 | 全文不是最后一句；总区间不超音频边界；部分失败、取消不冒充全部完成 |
| 停止可靠 | 尾句落库或缺口确认后才能结束。跨窗口抢先结束、末次确认失败、退出超时均不会产生假成功。旧轮次无法放行新轮次，无采音会议照常结束 |
| 授权与撤回 | 只允许已批准的目的地、用途、音源及当前任务；扩大范围须主持人确认。旧表单保留授权，原范围恢复免重复确认。撤回停传后无新增上传或重连，本机录音继续 |
| 文件重试 | “重新导入为新会议”先提示可能重复计费，生成新会议 ID 和新导入 ID，从头处理；旧会议的原音、已完成文本和失败位置均保留 |
| 安装包短测 | 仅使用最终签名 App 和测试账号，两种短测均能读取内嵌 helper 的样本并通过内容检查；缺资源时明确失败且没有上传 |
| 来源清楚 | 界面显示实际服务及音频流向；已结束记录不随默认设置变化 |
| 效果评估 | 单独报告真实中文样本的错字、术语、延迟和费用；短测通过不能代替长会验收 |

性能初始目标为正常网络下实时首段文字 2 秒内、停顿后最终文本 3 秒内。它们是待实测的验收目标；若达不到，要把实测分布及原因报告出来，不能写成已有保证。系统声与麦克风双路会形成两路云端识别消耗，费用按实际上传时长和厂商计费核算。
