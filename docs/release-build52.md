# Vera（真实交互）0.1.0 · build 52

历史记录。最终分发版本为 [Vera build 53](release-build53.md)，包含已在 GitHub 实际验证的服务账户兼容修正。

发布验证日期：2026-11-22。适用 Apple Silicon，最低 macOS 26。

产品英文名定为 **Vera（薇拉）**，取意于拉丁语 *veritas*（真实）。正式安装包使用 Vera 名称。本版清理发布源码、历史提交和构建产物中的个人路径与身份残留，并把检查接入后续构建、签名和发布流程。

## 下载与安装

下载 `Vera-0.1.0-build52-apple-silicon.dmg`，打开后将 Vera App 拖入 Applications。ZIP 提供相同应用。界面保留中文名称“真实交互”。首次配置见 [安装与首次使用](../native/DISTRIBUTION.md)。

源码及 Release 均通过原有 Private GitHub 仓库交付；下载者需要仓库访问权限。build 51 旧包在新版交付验证完成后撤下。

## 隐私整改

- 当前源码和全部发布可达历史清理个人绝对路径、真实会议名称与现场诊断数据。历史 author、committer 统一为 `Vera Contributors <dev@vera.invalid>`。改写在隔离副本完成，核对当前源码树完全一致后采用；原始历史备份只留在本机。
- 原生组件改为 Release 编译，映射源码前缀，并在签名前去除调试符号。最终两个原生程序均未发现个人 home 路径或本机用户名。
- 第三方许可目录只收集许可文本，重新生成前清理残留；移除误带入的源码模块与 Python 缓存，保留依赖许可署名及全部原有许可文本。
- 当前源码、完整历史、App、最终 DMG 和 ZIP 均通过同一个隐私检查器。冻结 Python 的 CArchive/PYZ、嵌套 ZIP、归档名称和元数据、macOS 资源旁车、符号链接也会检查；压缩内容无法读取时停止。
- 本次检查未发现真实服务 Key、私钥、会议数据库、录音或全量转写进入发布内容。允许的合成音频按内容哈希限制，不能仅靠改名绕过。

Developer ID 证书持有人的姓名、团队身份和第三方许可署名仍可读取，属于分发签名及许可的预期公开信息。检查通过不表示签名匿名，也不表示程序能识别任何未知自然语言中的个人信息。Git 历史改写及旧包下架不等于清除托管平台缓存或收回他人已下载副本。

## 防止后续重复发生

1. 桌面组装在临时签名前检查 App；正式签名前检查源码、完整历史和 App，并要求工作区干净、包内提交与源码一致。
2. 正式签名后、向 Apple 上传前再次检查 App；归档制作和公证后检查最终 ZIP、DMG。
3. 发布入口重新验证签名、票据、Gatekeeper、源码提交和归档哈希，仅允许四个附件：DMG、ZIP、SHA-256 文件、字段受限的验证回执。Apple 原始日志、本机报告和密钥不上传。
4. 发布入口要求 GitHub 仓库仍为 Private，标签及远端 main 对应当前提交；上传后比较四个附件的服务器 SHA-256。
5. GitHub Actions 对源码和完整历史执行检查。仓库提交身份使用本地匿名配置；额外本机敏感词只放本机私密词典，不进入 Git。

完整命令和边界见 [发布流程](../native/RELEASING.md)。
