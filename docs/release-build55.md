# Vera（真实交互）0.1.0 · build 55

验证日期：2026-11-22。适用 Apple Silicon，最低 macOS 26。

本版修复长录音云转写效率、关闭窗口导致任务停止、继续导入失败以及查证完成后耗时消失的问题。基线为 build 54；原有会议、录音、语音服务配置及 Apple 本机中文识别继续兼容。

## 修复

| 问题 | 原因与处理 |
| --- | --- |
| 阿里云文件转写逐分钟等待 | 客户端设置了 20 秒后的静音切分、60 秒上限，并串行等待上传和识别。阿里 Flash 改为 120 秒后按静音切分、最长 180 秒，最多 3 个并行请求。结果按音频顺序确认，内存和等待发布的片段数均有上限。 |
| 关闭窗口后任务停止 | macOS 最后一个窗口关闭会触发应用退出。改为保留应用和窗口对象，关闭窗口后任务继续，点击 Dock 图标可重新显示窗口。明确执行“退出真实交互”或 Cmd+Q 时仍会收尾退出。转写期间声明后台活动以避免 App Nap；不承诺系统睡眠时仍联网运行。 |
| 继续导入返回 409 | 同一录音、同一事件流恢复时从序号 1 重新发送，与已确认转写冲突。后端持久保存已接受序号，兼容从旧事件恢复序号；原生端在该序号后继续。已到音频末尾的断点允许直接重新收尾。 |
| 恢复后转写文件保存失败 | 原来向同一个部分转写文件写入不同内容，触发禁止覆盖保护。恢复后的内容另存带恢复次数的版本，部分转写文件继续保留；迟到的旧收尾不能覆盖新一轮状态。 |
| 查证完成后耗时消失 | 完成答案样式隐藏了耗时所在的状态行。完成后将耗时放到答案顶部，并使用保存的开始和结束时间显示“总用时”；刷新后保持不变。缺失结束时间的历史任务不根据后续编辑时间编造耗时。 |

继续导入复用已保存的原始音频和最后连续确认的位置，不创建新会议，不从头上传已确认内容。失败片段及其后的音频仍需重新识别。撤销授权、停止任务或请求失败时不越过未确认片段推进进度。

## 服务限制与选型

当前保留已配置的同步 Flash 接口。阿里官方文档列出该类接口最长 5 分钟；兼容旧 qwen3-asr-flash 的内联 Base64 限制时，16 kHz 单声道 PCM WAV 的 180 秒请求低于 10 MB，并在构造请求时再次校验体积。

官方提供的长录音异步 filetrans 接口需要公网可访问的音频 URL，是另一种接入方式。本版不自动把用户整场原音发布到公开地址，也不暗中切换模型；通过合规分段与有限并行优化现有接入。DeepSeek 文件协议和 Apple 本机识别保留原先处理方式。

参考：[阿里云录音文件识别](https://help.aliyun.com/zh/model-studio/qwen-speech-recognition)、[千问 ASR API](https://help.aliyun.com/zh/model-studio/qwen-asr-api-reference)。

## 验证

- 完整离线入口共 501 项：500 通过，1 项真实飞书 CLI 检查按条件跳过，无失败或错误。JavaScript 语法与三个原生可执行检查均通过。
- 回归覆盖旧事件序号恢复、部分文件保留与新版本保存、音频末尾重新收尾。
- 原生可执行回归使用 420 秒合成音频，覆盖分块并行、乱序响应按序提交、中间失败后断点保持、恢复序号和时间位置、任务取消及末尾不重传。
- 同一合成传输基线：旧逻辑 7 次请求、并发 1、约 1.06 秒；新逻辑 3 次请求、并发 3、约 0.46 秒。此为固定延迟桩测量，不能作为真实云服务提速承诺。
- 使用当前阿里配置执行真实接口验收，上传的内容为随包合成语音重复组成的 420 秒音频。3 段识别成功，范围为 0–180、180–360、360–420 秒，全部进度确认，耗时约 109.4 秒。未上传用户会议原音，此结果不代表真实会议准确率或相对旧版的云端速度基准。
- 原生窗口生命周期回归覆盖关闭后任务存活及重新打开；原有收尾保存重试、停止确认和超时回归继续通过。
- 隔离浏览器用合成查证数据复现 build 54 隐藏耗时，并确认修复后答案顶部显示“总用时 2 分 5 秒”、刷新保持。两个现有布局均可显示，切到尚未执行的问题会清除前一任务耗时。
- 全量离线入口为 `.venv-live/bin/python tools/verify_meeting_workbench.py --native`，详细结果在本机忽略目录 `outputs/review-build55/`。

正式安装包必须使用 Developer ID、安全时间戳、Hardened Runtime、Apple 公证及票据装订。安装包验证结果以 `release-verification.json` 和本版最终发布记录为准；流程见 [正式发布说明](../native/RELEASING.md)。不将会议数据、服务凭据、签名私钥或本机诊断日志放入提交和发布附件。

## 验证边界

没有第二台干净 Mac；没有重做真实会议长时间录音、休眠与设备切换验收。命令行环境不具备 XCTest 模块，使用实际生产 Swift 源码编译的可执行回归，不宣称 `swift test` 通过。真实云服务延迟、限流和识别准确率取决于服务及音频内容。
