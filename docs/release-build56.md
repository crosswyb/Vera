# Vera（真实交互）0.1.0 · build 56

验证日期：2026-11-22。适用 Apple Silicon，最低 macOS 26。

本版修复阿里云文件转写在长片段上反复失败的问题。此前请求已经成功恢复并推进进度，但有效的 HTTP 200 流式响应仍可能被客户端拒绝，表现为“语音服务返回的结果不完整或格式无效”。

## 修复

- 阿里流式响应会重复返回累计文本和句子信息，整段响应可超过 2 MiB。旧实现先收集整个响应，再按 2 MiB 总大小拒绝，误伤了有效结果。
- 生产网络路径改用 `URLSession.AsyncBytes` 逐条解析 SSE，只保留当前事件和最近的累计文本。单个事件、普通 JSON 响应和最终文本各自保留 2 MiB 上限，不再限制整个 SSE 流的累计大小。
- 字节解析在主线程之外执行，三个并发请求分别保留自己的解析状态。每个请求结束、解析失败或取消时关闭自己的网络任务；授权撤回时取消该会话。
- 保留 DeepSeek 普通 JSON、阿里累计文本、HTTP 错误分类和一次有界的 429 重试。真正超限时返回单独的 `speech_response_too_large` 错误。
- 不完整、格式错误或中途断开的响应不会确认片段；继续沿用最后连续确认的断点和已保存的部分转写。

## 验证

- 修复前，新增回归通过实际 `CloudFileRecognition.transcribe` 稳定复现有效大响应被拒绝；修复后通过。
- 使用 URLProtocol 驱动实际 `URLSession.AsyncBytes` 路径，覆盖约 2.36 MB 合法流式响应、三个并发请求、中文 UTF-8 拆帧、BOM、CRLF、多行 SSE 和 DeepSeek JSON。
- 错误回归覆盖单事件和 JSON 超限、无效 UTF-8、后续事件格式错误、尾部截断、服务端错误、429、连接中断、任务取消及授权撤回。已有累计文本不能掩盖后续错误。
- 420 秒合成音频回归覆盖并发乱序后按音频顺序确认、中间失败保持断点、从原位置恢复时处理大响应、事件序号连续、取消及音频末尾不重传。
- 完整离线入口 `.venv-live/bin/python tools/verify_meeting_workbench.py --native` 共 501 项：500 通过，1 项飞书 CLI 检查按条件跳过，无失败或错误；JavaScript 语法、原生协议及采音收尾回归通过。
- 对此前失败的单个 180 秒片段进行了真实阿里服务复验。生产流式路径收到 HTTP 200、2,276,633 字节响应并成功解析，识别 899 字，服务请求耗时约 31.8 秒。只发送这一段，未重新执行整个会议导入，也未修改原任务断点。单次复验不代表云服务延迟或识别准确率保证。

## 验证边界

没有第二台干净 Mac，未重做整场真实会议转写、长时间睡眠或设备切换验收。命令行环境使用实际生产 Swift 源码编译的可执行回归，不宣称 `swift test` 通过。服务限流、临时网络故障和识别质量仍取决于云服务及音频内容。
