# 真实交互 · Vera

开会时，有人问：“这项要求是国标里写的，还是我们自己定的？”大家记得看过，却说不准是哪一条。于是有人说“这个回头查一下”，会议接着往下开。可这条要求究竟怎么写，恰好决定了眼前的方案要不要改。

我做 Vera，是希望在大家还讨论这件事的时候，就能把那段原文摆到桌面上。再往远一点说，我想做的是**一个能跟你一起开会的贾维斯**。Vera（薇拉）这个名字取意于拉丁语 *veritas*，意为“真实”。

今天的 Vera 是一个 macOS 应用。它可以在开会时收听并转写，也可以读入已有录音。它结合前后文找出值得查证的问题，搜索资料，把简短的回答和依据放回对应的讨论旁边。你可以在 Mac 上看，也可以在手机飞书上看。让它自己申请发言、开口参与讨论，是我想做的下一步。

## 开会或听课时，怎么用？

**开方案评审会。** 点「开始会议」，选麦克风、电脑声音或两者。如果讨论中出现了刚才那个国标问题，Vera 会结合前面提到的对象和要求来识别问题。识别出来后，你可以从转写旁的便签打开查证结果。先看一句话结论，再按需要展开完整分析、来源和原文佐证。遇到标准或政策，尤其值得看「原文核验」：找到了哪份文件、能否定位到相关段落、还有什么没核实。找到一篇提到该标准的文章，和找到标准条文本身，证据分量不同。

**听一堂课。** 听网课时选电脑声音，坐在教室里可以选麦克风。如果老师讲到“工作流”和“智能体”的区别，你想知道这个区分最早是怎么定义的，可以手动添加这个问题，让 Vera 去找出处，自己继续听课。课后再打开这份查证文档，就能对照老师当时的讲法和查到的资料。已经录好的课也可以直接导入，无需从头播放一遍。

## 安装，试一次完整查证

安装包适用于 **Apple Silicon Mac，macOS 26 或更新版本**。在仓库的 **Releases** 中下载以 `Vera-` 开头的 DMG，把「真实交互.app」拖入「应用程序」，然后打开。安装包自带所需运行环境，无需另外安装 Python、Node.js 或知了 App。[安装与首次使用](native/DISTRIBUTION.md)

1. **选转写方式。** 打开「设置 → 语音转写」。第一次建议用默认的 Apple 中文识别，点「检查模型」，需要时点「安装模型」，等文件转写就绪。只想试录音和本地转写，做到这一步就可以导入了。
2. **打开查证能力。** 在「设置 → 模型与搜索」选择文字模型服务，填服务地址（Base URL）、模型名和 API Key。要查网页，再选择搜索服务并配置密钥。分别测试连接，点「保存模型与搜索设置」。
3. **导入一段有明确问题的短录音。** 点「导入音频」，例如选一段含有“请查一下这个术语最初是怎么定义的”的录音，最好在前一句说清术语名称。确认本场允许转写发给文字模型，并允许检索公开资料。可导入 WAV、M4A、MP3、AIFF、CAF、FLAC，单个文件上限为 2 GB、6 小时。
4. **看第一份结果。** 转写出现后，打开「查证问题」，选中问题看回答，再打开来源核对。短录音没有触发自动识别时，可以点「添加查证问题」试同一个问题。文件转写完成后可以继续查证；「结束会议」会暂停尚未完成的查证，会后仍可恢复或重试。

换成实时会议时，点「开始会议」，选好音源后点「创建并开始收听」。按 macOS 提示授权，在页面上看到实际转写，就说明收音到转写这一步跑通了。

## 更新应用

当前源码版在启动后自动检查更新，运行期间每 6 小时检查一次；发现新版时会在顶部提示。也可打开「设置 → 通用 → 软件更新」，查看当前版本、手动检查和阅读新版发布说明，再打开官方发布页下载 DMG。macOS 菜单栏的「真实交互 → 检查更新…」入口继续保留。

已发布的 build 57 可从菜单栏手动检查；build 56 及更早版本可直接从仓库的 Releases 下载。等会议、导入和查证任务完成后，退出 Vera，把新版拖进「应用程序」并选择「替换」。已有会议和设置保存在应用之外。

## 转写、文字模型与搜索，用哪些服务？

实时会议和导入音频可以分别选择转写方式。比如现场会议用 Apple 在本机识别，课后导入录音时再选云端。

| 语音识别方式 | 实时会议 | 导入文件 | 怎样启用 |
| --- | --- | --- | --- |
| Apple 中文识别 | 支持 | 支持 | 使用 macOS 的 `SpeechTranscriber`。在 App 内检查并安装中文模型，音频在本机处理，无需 Key。 |
| 阿里云百炼（DashScope） | 支持 | 支持 | 填百炼服务地址和语音 API Key。实时默认 `fun-asr-realtime`，文件默认 `qwen-audio-3.1-asr-flash`。分别用内置样本测试，通过后可选为对应用途的默认服务。 |
| DeepSeek 官方语音识别（ASR） | 不支持 | 支持 | 在语音转写设置中填写 DeepSeek API Key，文件转写测试通过后即可选用。 |

**文字模型**用来识别问题、分析资料和生成 AI 会议纪要。当前支持 DeepSeek 和兼容 OpenAI Chat Completions 协议的服务。**网页搜索**用来找外部来源，可选 DeepSeek Search 或 Tavily。Tavily 使用自己的 Key，同地址的 DeepSeek 搜索可复用 DeepSeek 文字模型的 Key。语音、文字和搜索是三个独立设置，第三方服务的用量计入你自己的账户。

**每场会议都可以决定哪些数据离开 Mac。** 选云端转写时，需确认将哪些音源或文件发给哪家语音服务。转写文字发给模型、检索词发给搜索服务另行授权。若想先看检索词，可以关闭自动检索，逐条确认。

## 在手机飞书上看结果

如果开会时 Mac 正在投屏，可以让新生成的查证结果出现在手机上。只有启用这项功能才需要在 Mac 上安装并初始化飞书官方 `lark-cli`。

1. 打开「设置 → 飞书同步」，连接账号，粘贴一个有写入权限的飞书云空间文件夹链接。
2. 选择「仅同步云文档」，结果会出现在手机飞书的对应文件夹。想在消息里收到提醒，选「同步云文档并通知群聊」，再选择一个自己能发言的群，并给需要看文档的成员阅读权限。
3. 勾选「自动同步新保存的查证结果」，保存后点「发送测试」，从手机打开测试文档。首次连接之前生成的文件不会自动补发。

## 会后能带走什么？

每场会议有自己的文件夹，默认位于 `~/Documents/ZSJH/Meetings/`。可以在「设置 → 通用 → 会议文件保存位置」打开或更换目录，新位置从下一场会议开始使用。

| 文件 | 内容 |
| --- | --- |
| 会议音频 | 实时录音默认归档为 M4A，可选额外保留原始 CAF。导入的录音保留原格式，源文件不变。 |
| `02-全量转录.md` | 整场会议已识别出的文字，可独立打开、搜索和引用。 |
| `03-会议纪要.md` | 会后总结。AI 总结需要可用的文字模型，只有本地摘录时会标为草稿。 |
| 按时间和问题命名的查证 `.md` 文件 | 每个问题单独成文，可带走回答、分析和来源。 |

会议资料长期保留。主动删除一场会议时，Vera 会列出将一并删除的本机文件并请你确认。已同步的文档和群消息在飞书中管理。

## 接下来想做什么

我希望有一天，团队在会上问“我们这个版本能做到吗”，Vera 能在议题结束前给出对这一版项目有用的回答。为此，我想往三个方向走：

- **让它能查自己的项目。** 除了公开网页，还能在授权范围内查本地知识库、设计文档和代码库。讨论某个功能时，它能指出文档怎么写、当前代码又实现到了哪里。
- **让它能动手验证。** 如果有人提议“改成这种方式就能跑通”，希望它能用一个小样例或已有测试试一下，把验证条件、实际结果和仍未覆盖的情况带回会议。
- **让它能开口参与。** 当手里有了足以影响讨论的证据，它可以申请发言，由参会者决定是否让它说；大家也可以追问或打断它。

会议纪要已经有了。从会上确认的决定生成待办，再交给对应的人或系统，也是以后可以接上的一步。我更想先做好的是前面这件事：当大家还坐在一起、还来得及改变决定时，就能把问题弄清楚一些。

## 从源码构建

在 Apple Silicon Mac 上准备 Python 3.11+ 和支持 macOS 26 SDK 的 Xcode 命令行工具。运行完整验证时还需要 Node.js 检查 JavaScript 语法。在仓库根目录执行：

```sh
python3 -m venv .venv-live
.venv-live/bin/pip install -r requirements-build.txt
.venv-live/bin/python tools/collect_dependency_notices.py
.venv-live/bin/python tools/verify_meeting_workbench.py --native
/bin/zsh tools/build_workbench_backend.sh
/bin/zsh native/scripts/build-desktop.sh
```

构建完成后可打开 `native/build/真实交互.app`。制作 DMG、ZIP 并进行正式签名和公证，请参阅[发布流程](native/RELEASING.md)。音频组件和本机后端见[原生开发说明](native/README.md)。
