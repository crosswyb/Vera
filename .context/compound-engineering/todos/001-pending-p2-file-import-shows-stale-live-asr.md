# 文件转写误显示实时采音服务

## 问题

Vera build 59 导入音频时，顶部进度和转写片段显示「DeepSeek 官方 ASR」，黄色状态栏同时显示「麦克风 · 阿里云百炼 · 转写中」和「电脑声音 · 阿里云百炼 · 转写中」。

## 已核对

- 2026-11-23 的本地任务记录显示文件转写已完成并保存。全部 256 段最终转写来源为 `file`、服务为 `deepseek`，本场实时采音记录为零。
- `static/workbench-speech.js` 的 `renderMeeting` 在桌面端绑定当前任务时合并桌面端的转写状态，已有任一来源时便跳过文件服务的显示。用 build 59 的脚本注入麦克风和电脑声音的百炼状态，复现了截图文案。
- `native/Sources/DesktopHost/DesktopHost.swift` 的 `beginCapture` 会清空 `transcription`，`beginFileImport` 切换到文件任务时未清空该状态。具体是上一场哪次采音留下了截图中的状态，尚未核实。

## 修复选项

- 按任务类型渲染转写状态。文件任务读取自身的服务和文件状态，实时任务继续显示各采音来源。
- 桌面端在绑定新文件任务前清空实时采音状态，并核对状态发布时序。前端仍按任务类型取状态，可防止旧值再次混入。

## 建议动作

在修复前用模拟状态或隔离测试数据覆盖实时采音结束后导入文件的路径，保留文件任务的音频上传授权、撤回状态和转写缺失提示。

## 验收

- [x] 实时转写配置为百炼，从麦克风及电脑声音的采音任务切换到 DeepSeek 文件转写。黄色栏显示本次文件服务，顶部、片段来源和状态栏一致。
- [x] 实时任务仍能分别呈现两个来源的状态。
- [x] 文件任务的授权撤回、转写异常和缺失提示仍能正常显示。
